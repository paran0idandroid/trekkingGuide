# Decisions — 技术决策记录

## 已确定的决策

### ADR-001: 纯前端 SPA，无后端（已被 ADR-012 部分取代）

**2026-06-14**

所有数据以 TypeScript 模块硬编码在 `src/data/` 中，无后端 / 数据库 / API 依赖。静态资源通过 Vite 构建后部署到 Netlify。

**理由**：
- 内容量适中，不需要数据库
- 部署简单，零运维
- 页面加载快，无网络请求延迟

**影响**：内容更新需要修改源码后重新部署。推荐使用 AI 辅助编辑数据文件。

**后续变化**：路线、地图、装备知识和推荐仍遵循本决策；个人装备清单自 2026-08-08 起改用本地 Node API 与 SQLite，见 ADR-012。

---

### ADR-002: Tailwind CSS 自定义色板

**2026-06-14**

定义 `forest`（墨绿）和 `sand`（沙色）两个色系，各 9 级（50–900）。

**理由**：
- 与户外徒步主题吻合
- 不需要额外 CSS-in-JS 方案
- Tailwind 的 utility class 覆盖全部场景

**影响**：所有颜色值引用必须走 Tailwind 调和色板（如 `text-forest-500`），不直接写十六进制颜色。

### ADR-003: 装备推荐系统 — 纯前端规则引擎（路线详情流程已被 ADR-017 取代）

**2026-06-14**

装备推荐不依赖 AI / 外部 API。用纯函数实现匹配逻辑（`src/lib/gearEngine.ts`），产品数据硬编码在 `src/data/gearCatalog.ts`。

**理由**：
- 推荐逻辑可预测、可测试
- 零运行时成本
- 离线可用

**影响**：推荐精度受限于产品数据库规模和规则粒度。需要人工维护产品库。

**后续变化**：路线详情中的问答、规则引擎与结果页自 2026-08-10 起删除；装备知识页的独立轻量顾问继续保留，见 ADR-017。

### ADR-004: 中文 UI + 英文代码

**2026-06-14**

UI 文案、URL 路径、注释使用中文。TypeScript 标识符（类型、变量、函数名）使用英文。

**理由**：
- 目标用户为中文徒步爱好者
- 保持代码在编辑器中的可读性和工具链兼容性

**影响**：团队成员需具备双语阅读能力。

### ADR-005: 数据与视图分离

**2026-06-14**

路由数据集中在 `src/data/routes.ts` 注册，每条路线的完整数据定义在 `src/data/routeData.ts`。组件只接收 props 或通过 slug 查询数据，不直接持有数据定义。

**理由**：
- 数据可独立测试
- 新增路线只需添加数据文件，不修改组件
- 组件可复用

**2026-06-14**

**理由**：

### ADR-007: WebP 图片格式

**2026-06-14**

所有静态图片使用 `.webp` 格式存放在 `public/pics/`。

**理由**：
- 相比 JPEG/PNG 压缩率高，加载更快
- 所有现代浏览器均支持

### ADR-008: 乌孙古道使用 MapLibre + MapTiler Outdoor

**2026-07-12**

乌孙古道交互地图使用 MapLibre GL JS 渲染本地 GeoJSON 轨迹与节点，底图使用 MapTiler Outdoor。API Key 仅通过 `VITE_MAPTILER_API_KEY` 注入，不写入源码或 Git。

**理由**：
- 支持矢量地形、等高线、山体阴影和专业路线交互
- MapLibre 维护活跃且许可证适合项目使用
- 本地 GeoJSON 可移除 KML 中的用户和设备元数据

**影响**：MapTiler 是外部运行时服务；生产部署前必须配置带 HTTP Origin 限制的独立 Key。

### ADR-009: Satoshi + Nohemi + Noto Sans SC 字体体系

**2026-07-13**

正文、导航和按钮使用 Satoshi；h1–h3 使用 Nohemi；中文统一回退到 Noto Sans SC。Satoshi 从 Fontshare 官方 Web Font 加载，Nohemi WOFF2 随项目发布并保留许可文件。

**理由**：
- 建立更接近 Komoot 的户外产品字体层级
- 保持中文跨平台可读性
- Nohemi 本地托管避免标题字体受第三方网络影响

**影响**：Satoshi 仍依赖 Fontshare CDN；字体来源和许可见 `third-party-licenses/README.md`。

### ADR-010: 路线节点名称与选中聚焦规则

**2026-07-13**

节点名称直接由 MapLibre Symbol 图层绘制。桌面显示全部节点名；移动端首屏显示起点、终点、营地和垭口，河流与景点在 zoom 11 后显示。选中态使用深绿双环并保持标签原有深绿文字与白色细描边。

节点聚焦以可见地图区域为中心：桌面向右偏移 335px，避开左侧 670px 双卡片；移动端向上偏移地图高度的 39%，避开 78vh 详情面板。

**理由**：
- 节点无需打开列表即可识别
- 避免粗描边形成突兀的矩形色块
- 列表点击后节点不会被桌面卡片或移动端详情面板遮挡

**影响**：卡片宽度、响应式断点或移动端面板高度变化时，必须同步复核聚焦偏移。

### ADR-011: 哈巴西坡轨迹来源、隐私与地图复用

**2026-07-19**

哈巴西坡以用户实际活动 FIT 作为权威轨迹几何，合并 KML 只用于关键点名称与参考位置。离线转换后只发布三日坐标、海拔、日序号和 8 个公共关键点；原始 FIT、KML、时间戳、心率、配速、设备和用户信息均不进入项目。

路线复用现有 MapLibre 交互组件，但使用独立的 `RouteData`、`RouteMapConfig` 和 `haba-west.geojson`。地图 layer ID 按 route slug 隔离；三日轨迹分别着色并共享动态方向处理。

**理由**：
- FIT 对应用户实际走过并返回起点的闭环路线，几何可信度高于合并 KML
- 脱敏 GeoJSON 满足公开展示所需的最小数据原则
- 复用已验证的地图交互，避免复制乌孙专属组件，同时保持两条路线数据独立

**影响**：哈巴西坡照片与可靠水源信息仍待补充；加入照片时只使用 `/pics/*.webp` 数据字段，不修改地图组件。

### ADR-012: 个人装备使用单机 Node API 与 SQLite

**2026-08-08**

`npm run dev` 由一个 Node 进程在 `localhost:58514` 同时提供 Vite 页面和 `GET/PUT /api/gear`。个人装备保存到项目 `.local-data/gear.sqlite`，前端只通过 API 读写，并用递增 revision 检测旧快照覆盖。

**理由**：
- 数据不再依赖浏览器、登录状态或页面来源，关闭浏览器和项目进程后仍保留
- SQLite 文件便于本机确认和备份，不需要新增 npm 依赖
- revision、事务和字段校验能避免多标签页静默覆盖或写入非法清单

**影响**：该模块目前是单机单用户能力，不提供跨设备同步；`.local-data/` 必须保持 Git 忽略。静态 Netlify 部署不能直接承载此本地 API，正式部署前需要另行决定服务端方案。

### ADR-013: 个人装备复用六大系统并采用双清单

**2026-08-09**

个人装备分为“已有装备”和“待购买”两个状态。已有装备按背负与收纳、庇护、睡眠、穿着与行进防护、饮食与补水、导航与安全六大系统展示；待购买保持紧凑单列。“已买到”会保留系统归属并移入已有装备。

**理由**：已有装备需要建立完整装备结构，采购阶段则需要快速记录和勾选。两种信息密度使用不同布局，比在所有状态下强制六分组更清晰。

**影响**：名称在两个状态之间全局去重；自动归类无法判断的条目需要用户手动选择系统。

### ADR-014: “我的装备”采用分层 Liquid Glass

**2026-08-09**

顶部导航保持白色，导航以下使用全宽 forest/sand 环境背景。装备模块、分段控件、按钮和操作面板使用光学透镜式双层边缘、折射高光与背景色散；桌面保持 3×2 紧凑看板，移动端使用单列与底部操作面板。

**理由**：在保留 44 件装备阅读密度的同时，让 iOS 风格材质在手机和网页端均清晰可见，并消除桌面两侧及底部的纯白断层。

**影响**：必须继续支持 `prefers-reduced-motion`、`prefers-reduced-transparency` 和高对比模式；不得用循环动画或额外依赖模拟玻璃效果。

### ADR-015: 项目收敛为本地单用户体验

**2026-08-10**

删除手机号登录、收藏页、收藏按钮及其 localStorage 服务。导航只保留地图、装备知识和我的装备；个人装备继续通过本机 Node API 与 SQLite 持久化。

**理由**：项目当前只供本人在本机体验，认证和收藏增加了无实际价值的状态与入口。

**影响**：旧 `/auth` 和 `/favorites` 地址返回首页；不主动清理浏览器中遗留的旧键值。

### ADR-016: 全国地图统一使用 MapLibre Outdoor

**2026-08-10**

首页全国地图从 ECharts 切换为与路线详情一致的 MapLibre + MapTiler Outdoor。全国尺度只显示乌孙古道与哈巴西坡的地点标记和名称；点击直接进入详情。不存在的珠峰东坡路线及专用图片已删除，哈巴 `scene-1.webp` 同时作为首页首屏和路线卡片封面。

**理由**：统一地图框架与视觉语言，移除模拟路线线条和第三套边界数据依赖，并确保路线目录只展示真实存在的内容。

**影响**：全国地图与路线详情共用 `VITE_MAPTILER_API_KEY`；缺少 Key 时显示明确错误，不使用 ECharts 回退。

### ADR-017: 路线详情聚焦地图与单一概况模块

**2026-08-10**

进入路线详情时立即回到地图顶部；删除地图下方的重复摘要条和路线专属装备推荐流程。路线概况继续使用四张 Liquid Glass 数据卡，通过收敛数值字号、禁止换行并增强标签与说明文字对比度保持桌面和移动端可读性。

**理由**：路线详情的首要任务是查看路线地图与关键数据；重复摘要和悬浮推荐按钮会分散注意力，过大的数值也会破坏长距离及海拔数据的排版。

**影响**：装备知识页的独立顾问和个人装备 SQLite 清单不受影响；路线卡片导航必须重置滚动位置。
