# 极简待购买装备清单设计

## 目标

“已有装备”继续使用六大系统看板；“待购买”改为一个不分板块的紧凑单列清单，让用户快速记录采购事项，并在买到后自动进入已有装备的正确系统。

## 页面结构

- 顶部继续显示“已有装备 / 待购买”状态标签和两组数量。
- 已有装备页面保持当前六大系统看板、系统内添加和待归类区域。
- 待购买页面只显示：
  - 一个统一的“添加待购买装备”入口。
  - 一个紧凑单列清单。
  - 每行的装备名称和“已买到”按钮。
- 待购买页面不显示六大系统标题、系统数量、代表装备或分类标签。

## 自动分类与手动修正

- 新增待购买装备时调用现有本地纯函数 `inferGearSystem(name)`，把判断结果保存到条目的 `systemSlug`。
- 扩展关键词规则，覆盖本次清单中的帐篷、地布、睡垫、背包罩、托运袋、雨衣、营地鞋、炊具、净水、急救、北斗和照明等名称。
- 点击“已买到”只把状态从 `wanted` 改为 `owned`，保留 `systemSlug`，装备随即出现在已有装备的对应系统。
- 无法判断的装备保存为 `systemSlug: null`，买到后进入已有装备的“待归类”区域。
- 点击待购买装备名称可展开“编辑名称 / 更改系统 / 删除”；更改系统使用六大系统选择框。
- 已有装备继续保留现有的手动更改系统能力。

## 数据

- 用户提供的 25 件装备写入当前浏览器、当前清单所有者的 IndexedDB。
- 这些条目不硬编码到源码，不会自动出现在其他手机号或其他浏览器中。
- 新增时继续执行全局名称去重，忽略首尾空格和英文大小写。
- 若当前清单已经存在同名装备，保留原条目并跳过重复项，不覆盖状态或创建时间。

## 组件边界

- `GearInventory` 继续负责加载、保存、状态切换和全局校验。
- `GearInventorySystemCard` 只服务已有装备的六大系统看板。
- 新增默认导出的 `WantedGearList`，负责待购买的统一添加、单列展示、名称操作层和“已买到”入口。
- `gearInventory` 扩展关键词表；IndexedDB 数据结构和数据库版本不变。

## 交互与可访问性

- 待购买装备名称为可点击按钮，沿用现有 `gear-pressable`、清晰的 `forest-500` 键盘焦点和操作层动画。
- 移动端名称、“已买到”和确认操作保持至少 44px 触控高度；桌面端保持紧凑。
- 编辑、改系统和删除确认接管焦点，取消后回到原装备名称。
- 删除仍需行内二次确认。

## 验收

- 待购买页面完全不渲染六大系统板块，只显示统一添加入口和单列清单。
- 新增装备会自动保存系统归属，并可在操作层手动修改。
- “已买到”后装备进入已有装备的正确系统，未知装备进入待归类。
- 25 件用户装备全部存在于当前 IndexedDB 的待购买清单，刷新后仍保留。
- 全局重名校验、手机号/访客隔离和同步写锁保持正常。
- 1440×900 与 390×844 下完成添加、编辑、改系统、已买到、删除确认和持久化 QA。
- 全量 Node 测试、Vite production build 与 `git diff --check` 通过；本次文件不新增 TypeScript 诊断。
