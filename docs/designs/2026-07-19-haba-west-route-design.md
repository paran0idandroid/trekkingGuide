# 哈巴西坡路线介绍设计

## 目标

将用户实际走过的 FIT 轨迹制作成一条独立的新路线“哈巴西坡”，提供与乌孙古道一致的专业交互地图、关键点定位和完整路线介绍，同时不改变乌孙古道与珠峰东坡的现有内容和体验。

本路线暂不使用图片。页面先完整呈现地图、概览、三日行程、风险与装备建议；待用户提供照片后，再通过路线数据补充图片内容。

## 已确认范围

包含：

- 新增独立路由 `/route/haba-west`
- 使用 FIT 实际轨迹生成三日闭环路线
- 三日轨迹使用同一森林绿色系的三个层级区分
- 8 个关键点的地图标注、列表选择、自动聚焦与文字介绍
- 桌面端双卡片交互和移动端底部抽屉交互
- 路线概览、三日行程、风险、补给通信与装备建议
- 暂无图片时的完整无图布局
- 对乌孙古道和珠峰东坡进行回归验证

不包含：

- 展示个人运动记录、心率、配速、时间戳或设备信息
- 将原始 FIT 或参考 KML 发布到网站
- 实时导航、在线规划、轨迹编辑或 GPX 下载
- 为路线生成或临时填充占位图片
- 修改现有路线的数据或视觉内容

## 数据来源与优先级

### 实际轨迹

权威几何来源为用户本人走过的私有 FIT 附件。原始文件名、本机路径与活动标识不写入仓库。

文件已通过 Garmin 官方 FIT JavaScript SDK 离线解析并通过 CRC 校验。解析结果确认：

- 活动类型为徒步
- 20,691 个有效 GPS 坐标记录
- 实际记录距离约 22.55 千米
- 累计爬升 1,571 米，累计下降 1,574 米
- 轨迹跨三天并返回起点，属于闭环路线
- 路线最高记录海拔 4,384 米

FIT 只在离线转换阶段使用，不能复制到项目或随网站发布。

### 关键点参考

关键点名称与参考位置来自用户提供的私有 KML 附件。原始文件名与本机路径不写入仓库。

该 KML 是合并路线，只用于辅助定位和命名，不替代 FIT 的实际轨迹。出现差异时按以下优先级处理：

1. 轨迹几何与分日边界以 FIT 为准。
2. 页面关键点名称以用户确认的名称为准。
3. KML 只用于把关键点吸附到实际 FIT 轨迹附近。
4. 页面行程距离使用用户确认的路线介绍距离，不使用运动记录距离。

## 路线事实

### 页面概览

- 名称：哈巴西坡
- 副标题：穿越双湖、黑海与连续高山垭口的三天两夜环线
- 总距离：23.3 千米
- 行程：3 天 2 夜
- 累计爬升：1,571 米
- 最高海拔：4,384 米
- 难度：中高
- 最佳季节：5–9 月
- 适合人群：有高海拔徒步和露营经验的徒步者

总距离 23.3 千米来自三日路线介绍距离之和；FIT 记录的约 22.55 千米只用于轨迹几何校验，两者不能在页面上混用。

### 三日行程

1. 第一天：咖啡营地（徒步起点）→ 双湖营地，5.7 千米。
2. 第二天：双湖营地 → 双湖垭口 → 夫妻海垭口 → 黑海垭口 → 黑海营地，7.1 千米。
3. 第三天：黑海营地 → 长湖 → 鸡趾垭口 → 咖啡营地（徒步终点），10.5 千米。

起点和终点坐标基本重合，地图只绘制一个“咖啡营地（起点/终点）”节点，避免两个标记互相覆盖。

### 关键点与展示海拔

| 关键点 | 海拔 | 说明 |
|---|---:|---|
| 咖啡营地（起点/终点） | 3,465 米 | 闭环路线的出发与返回位置，也是全程唯一明确有手机信号的位置 |
| 双湖营地 | 4,071 米 | 第一天营地，采用 FIT 第一天结束位置 |
| 双湖垭口 | 4,378 米 | 第二天连续垭口路段的高点之一 |
| 夫妻海垭口 | 4,369 米 | 使用用户确认名称，不采用 KML 中的“夫妻湖垭口” |
| 黑海垭口 | 4,211 米 | 位于第二天前往黑海营地的轨迹上 |
| 黑海营地 | 4,110 米 | 第二天营地，采用 FIT 第二天结束位置 |
| 长湖 | 4,168 米 | 使用用户确认名称，KML 中邻近点“小黄海”仅作为定位参考 |
| 鸡趾垭口 | 4,318 米 | 使用用户确认名称，不采用 KML 中的“吉支垭口” |

关键点海拔来自吸附后的 FIT 轨迹点。路线最高海拔 4,384 米是整条 FIT 轨迹的最大值，因此可以高于任一命名关键点的展示海拔。

## 数据与组件架构

### 路线数据

- 在 `routeData.ts` 定义完整的 `habaWestRoute`。
- 在 `routes.ts` 将 `haba-west` 注册到唯一的路线数据入口。
- 在云南地区数据中登记该路线，使地区查询能够返回哈巴西坡。
- 页面与组件继续只通过 `getRouteBySlug()` 和 `getRoutesByRegion()` 获取路线数据，不直接导入具体路线常量。

### 地图数据

新增独立文件 `public/routes/haba-west.geojson`，包含：

- 三个按天划分的 `LineString` 轨迹要素
- 8 个公开关键点 `Point` 要素
- 渲染所需的日序号、稳定 ID、名称、分类与海拔

GeoJSON 必须移除：

- 时间戳
- 心率、配速和逐点运动指标
- 设备、平台、用户或活动 ID
- FIT 与 KML 中其他个人元数据

原始 FIT 和 KML 不进入 `public/`，也不提交到 Git。

### 地图配置

在现有路线地图配置层增加完全独立的哈巴西坡配置，包括：

- 地图视野与轨迹范围
- 三日轨迹颜色和图例
- 关键点数据及文字介绍
- 路线摘要与移动端文案
- GeoJSON 地址

将地图组件中仅属于乌孙古道的硬编码内容改为由当前路线配置驱动，包括 source/layer ID、无障碍名称、列表标题、摘要统计和节点内容。只抽取哈巴西坡复用所必需的部分，不建立超出两条地图路线需求的通用框架。

乌孙古道继续使用自己的配置和 GeoJSON；珠峰东坡继续使用原有图片 Hero。

### 图片字段

路线 Hero 和节点图片改为可选字段。没有图片时：

- 地图直接作为页面首屏主视觉
- 节点列表和详情使用纯文字布局
- 不渲染空白图片框、占位图或失效图片
- `highlights` 为空时不显示路线亮点图片区域

未来收到图片后，只需在哈巴西坡路线数据中加入 `/pics/*.webp` 路径，不再修改组件布局。

## 地图视觉设计

### 三日轨迹

三天路线使用同一森林绿色系的三个层级：

- 第一天：浅森林绿
- 第二天：标准森林绿
- 第三天：深森林绿

每段轨迹均保留白色外描边，确保在等高线、山体阴影和不同地表上可读。动态方向效果沿用乌孙古道已经验证的处理方式，并分别应用到三段轨迹。

地图提供紧凑图例，显示每天的颜色、距离和起止点。图例不能遮挡地图署名或主要控件。

### 节点样式

未选中节点沿用乌孙古道当前的圆点、中文名称和白色文字包边。选中节点沿用已确认的深绿色双环高亮，不使用突兀的长方形标签背景，也不反转名称颜色。

起终点合并节点的名称为“咖啡营地（起点/终点）”。

## 页面结构与交互

### 桌面端

地图作为详情页顶部主视觉，左侧沿用乌孙古道的双卡片结构：

1. 第一张卡片列出 8 个关键点。
2. 第二张卡片默认显示路线摘要，选中节点后显示该节点的文字介绍。

用户点击左侧关键点后：

- 地图平滑缩放并移动到对应位置。
- 目标节点显示双环高亮和名称。
- 详情卡片切换到对应节点介绍。
- 地图把节点放在两张卡片右侧的可见区域，不让卡片遮挡节点。

点击地图上的节点圆点或名称时，触发相同的选中与详情逻辑。

### 移动端

沿用乌孙古道三段式底部抽屉：

1. 收起状态显示路线名称和核心统计。
2. 中间状态显示关键点列表。
3. 展开状态显示当前节点的完整文字介绍。

从列表或地图选择节点后，地图将节点移动到抽屉上方的可见区域。抽屉拖动与地图平移手势保持隔离。

### 无图内容结构

哈巴西坡暂时不显示图片：

- 节点卡片只显示名称、海拔、所属天数和简要定位信息。
- 节点详情使用清晰的文字层级展示环境、行程位置和注意事项。
- 页面下方保留概览、三日行程、风险和装备内容。
- 不出现空图片比例框，不使用与实际路线无关的图库照片。

## 风险、补给与装备文案

页面必须明确提示：

- 路线属于中高难度高海拔徒步，需要高海拔行走和露营经验。
- 部分路段存在陡峭雪坡，应根据当季积雪判断通行条件，并准备相应防滑与安全装备。
- 全程无可靠补给，重装徒步需要自备露营、食物和燃料。
- 轻装方式依赖当地马帮运输装备，出发前必须确认服务与行程。
- 除起点外全程基本没有手机信号，应提前下载离线地图并准备离线通信或应急方案。
- 沿途可靠饮用水源信息不明确，不应把湖水或溪流视为稳定补给。出发前需向当地向导或马帮确认当季水源，并携带足够饮水及净水设备。

不把用户没有确认的水源、补给点或通信覆盖写成确定事实。

## 错误处理

遵守项目“不做隐式兜底”的原则：

- 哈巴西坡地图配置缺失时暴露明确错误，不借用乌孙古道配置。
- GeoJSON 加载失败时显示中文错误状态，不绘制示意轨迹。
- 节点 ID 与 GeoJSON 不一致时暴露开发错误，不静默选择其他节点。
- 没有图片是合法的数据状态，不按图片加载失败处理。
- 地图初始化失败时，下方路线文字内容仍可阅读。

## 验证与验收标准

### 数据验证

- GeoJSON 包含 3 条分日轨迹和 8 个唯一关键点。
- 三段轨迹按 FIT 日期边界连续衔接。
- 第三段最终返回第一段起点，形成闭环。
- 路线概览显示 23.3 千米、3 天 2 夜、累计爬升 1,571 米、最高海拔 4,384 米。
- 三日介绍距离分别显示 5.7、7.1、10.5 千米。
- 关键点名称与海拔符合本设计表格。
- 发布文件中不含时间戳、心率、配速、设备信息、用户 ID 或活动 ID。

### 交互验证

- 点击列表和点击地图节点会选中同一个详情。
- 选中节点使用双环样式，名称没有长方形高亮背景。
- 桌面端聚焦后节点位于双卡片右侧，不被遮挡。
- 移动端聚焦后节点位于底部抽屉上方，不被遮挡。
- 三日轨迹颜色和动态方向清楚可辨，图例内容正确。
- 起终点只显示一个合并节点。

### 无图布局验证

- 页面不请求不存在的图片。
- Hero、节点详情和路线亮点区域不出现空白图片框或破图。
- 纯文字节点详情在桌面端和移动端均具有清晰层级。

### 回归验证

- 乌孙古道的底图、轨迹、标签、双环选中效果、节点聚焦和双卡片布局保持不变。
- 珠峰东坡的 Hero、图片和正文保持不变。
- 现有路线查询和地区查询继续正常工作。

### 工程与浏览器验证

- 纯函数或状态逻辑先补充可执行测试，再实现功能。
- 现有 Node 地图状态测试和新增测试全部通过。
- TypeScript 严格模式与 `npm run build` 通过。
- 完成桌面浏览器 QA。
- 完成 390 × 844 移动端 QA。
- 按 AGENTS.md 逐项检查数据入口、颜色、图片路径、默认导出和依赖约束。

- 海拔剖面与地图位置联动
