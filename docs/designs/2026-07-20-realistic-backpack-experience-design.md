# 真实徒步背包 3D 体验设计

## 1. 目标

将现有装备知识模块中的“查看 3D 结构”升级为一段完整、真实且可学习的背包空间体验：用户先进入高山环境建立徒步语境，再聚焦到产品棚拍式的真实徒步背包，通过热点和结构拆解理解背包的主要组成。

本阶段只实现背包原型，不扩展到其余五大装备系统，也不新增独立路由或第三方依赖。

## 2. 已确认的体验方向

- 视觉：尽可能真实，不采用低多边形、卡通或战术背包替代。
- 对象：无品牌感的 55–65L 重装徒步背包。
- 入口：沿用现有装备页面中的“查看 3D 结构”。
- 形态：全屏沉浸体验，而不是嵌在普通知识卡片中的小型模型窗口。
- 主流程：高山开场 → 产品棚拍 → 结构热点 → 五组结构拆解 → 知识抽屉。
- 动效：GSAP 负责编排阶段和界面动画，React Three Fiber / Three.js 负责模型、镜头和灯光。
- 内容：继续复用 `gearAnatomyData`，不在 3D 组件中复制知识正文。

## 3. 用户流程

### 3.1 进入与开场

用户点击“查看 3D 结构”后进入全屏体验。首屏用克制的高山氛围、远景层次和简短引导建立徒步语境；背包模型资源在此阶段按需加载，页面显示明确的加载进度。

资源准备完成后，镜头由高山环境过渡到干净、安静的产品棚拍空间，背包成为唯一视觉中心。用户可以点击“跳过动画”直接进入可交互状态。

### 3.2 自由观察

进入棚拍阶段后，用户可以拖动旋转并缩放背包。界面提供简短操作提示，但不持续遮挡模型。热点随对应结构移动，并在被遮挡时降低存在感，避免穿透模型造成错误指向。

### 3.3 热点学习

点击热点后：

1. 镜头平滑转向对应部位；
2. 当前部位以轮廓、局部材质或轻微位移高亮；
3. 右侧知识抽屉显示该结构的作用和使用要点；
4. 用户可以继续选择其他热点，或关闭抽屉回到自由观察。

肩带、腰带和底部防雨罩采用热点定位，不虚构源模型中不存在的独立几何结构。

### 3.4 结构拆解

用户点击“拆解结构”后，模型的五组真实几何沿可读方向分离，形成结构爆炸视图：

- 主仓；
- 顶包；
- 背负系统；
- 前部与外挂收纳；
- 扣具与压缩系统。

拆解仅用于解释结构关系，不模拟真实拆装步骤。用户可以随时恢复完整背包。

## 4. 模型资产与许可

使用用户提供的 Sketchfab 模型归档：

- 名称：Hiking Backpack；
- 作者：kam；
- 来源：https://sketchfab.com/3d-models/hiking-backpack-ffd0bd8f61034f17a90e41fe8f2da003；
- 许可：CC BY-SA 4.0。

项目必须保留作者、模型来源、许可链接和修改说明。经优化或重新导出的模型属于衍生作品，继续以 CC BY-SA 4.0 提供。归属信息在 3D 体验的“模型信息”入口中可见，并随模型资源保留许可证文件。

原始 glTF 资产约 20 万三角面，包含 32 个可独立访问的网格和多张 4K/2K 贴图，具备实现真实结构拆解的基础。原始资源不会直接作为正式前端资产发布，需先完成针对网页端的优化。

## 5. 网格分组

新增一个纯数据映射模块，将 glTF 中的网格名称映射到五组产品语义。组件只读取该映射，不在渲染代码中散落网格名称。

| 结构组 | 模型网格 | 交互用途 |
| --- | --- | --- |
| 主仓 | `body_l001` | 主体高亮与拆解 |
| 顶包 | `atas_l001` | 顶包高亮与拆解 |
| 背负系统 | `back_l001`、`pipe_l001`、`strap_l001` | 背板、支撑与织带整体拆解 |
| 前部与外挂收纳 | `depan_l001` | 前袋和外挂区域拆解 |
| 扣具与压缩系统 | `clip*`、`zio_l001` | 扣件、压缩与拉链结构拆解 |

映射模块在开发环境中验证所有必需网格是否存在。缺少必需网格时直接显示可理解的资源错误，不静默切回旧模型。

## 6. 组件职责

### `GearAnatomyViewer`

保留为现有入口和顶层编排组件，负责全屏开关、体验阶段、当前热点、抽屉状态、跳过与退出，不直接操作 glTF 网格。

### `BackpackOpeningScene`

负责高山开场、加载进度、跳过入口和向棚拍空间的视觉过渡。背景采用轻量的场景组合，不为了开场引入第二个大型 3D 资产。

### `RealisticBackpackModel`

负责加载和渲染优化后的真实模型、轨道控制、镜头聚焦、热点锚点、高亮、结构拆解和恢复。模型只在体验打开后加载。

### `backpackModelParts`

纯数据模块，保存网格分组、爆炸方向、热点锚点和对应知识 ID。它不依赖 React，便于独立校验。

现有 `BackpackModel` 的程序化方块模型在真实模型通过验收后移除，避免维护两条主流程。

## 7. 状态设计

体验使用有限、显式的阶段状态：

- `opening`：高山开场与资源加载；
- `studio`：完整背包自由观察；
- `focused`：镜头聚焦并显示知识抽屉；
- `exploded`：五组结构拆解；
- `error`：模型资源无法加载。

阶段切换由顶层组件统一控制。GSAP 时间线在组件卸载、退出体验或重新开始时完整清理，避免重复进入后叠加动画。

## 8. 性能与资产处理

- 正式模型目标体积为 6–10 MB；若无法达到，应先减小贴图而不是牺牲背包轮廓。
- 主体材质贴图缩放到最高 2K，次要材质最高 1K。
- 合并可安全合并的静态几何，但保留五组拆解所需的网格边界。
- 清理未使用材质、贴图和重复顶点；优化后重新检查法线、UV、材质和网格名称。
- 桌面端使用接触阴影和较高渲染精度；移动端降低 DPR 与阴影质量，不移除核心热点和拆解功能。
- 模型在入口打开后懒加载，不增加装备首页的初始下载负担。

不新增模型压缩运行时依赖。资产优化使用已有工具链能够完成的离线处理；若现有环境不能稳定产出目标资源，则先停在可验证的未压缩版本并明确记录体积，不用静默降级掩盖问题。

## 9. 动效与无障碍

- 开场和镜头动效保持节奏明确，避免持续漂浮、夸张弹性或无意义循环。
- 支持 `prefers-reduced-motion`：跳过开场和自动镜头飞行，直接进入稳定的棚拍状态；热点与知识内容仍可操作。
- 所有核心操作可通过按钮完成，不把拖拽作为唯一交互方式。
- 热点按钮提供可读中文名称、清晰焦点态和足够点击区域。
- 知识抽屉打开后维持合理的焦点顺序，关闭后焦点回到原热点。

## 10. 错误处理

模型加载失败时进入明确的 `error` 状态，提供：

- 错误说明；
- “重新加载模型”；
- “返回装备指南”。

不吞掉加载异常，也不自动展示旧的方块背包作为替代，因为这会让资源问题难以被发现。

## 11. 验收标准

- 从现有“查看 3D 结构”进入全屏体验，无新增路由。
- 高山开场、棚拍观察、热点聚焦、知识抽屉、五组拆解和恢复形成完整流程。
- 正式页面展示真实徒步背包，不再显示程序化方块模型。
- 五组结构映射均能找到真实网格；肩带、腰带和防雨罩热点位置合理。
- 模型加载进度、错误、重试、跳过和退出均可用。
- 刷新和重复打开体验不会残留 GSAP 动画或 Three.js 资源。
- `prefers-reduced-motion` 下不播放开场和自动镜头飞行。
- 桌面与手机均可完成核心操作，手机无文字或控制项溢出。
- 模型作者、来源、许可和修改说明可访问，许可证随资产保留。
- 未新增 npm 依赖；TypeScript 严格检查、Vite 构建和 `git diff --check` 通过。
- 浏览器 QA 覆盖正常流程、拆解恢复、热点切换、加载失败、移动端和减少动效模式。

## 12. 非目标

- 本阶段不为其余五大装备系统制作 3D 模型。
- 不实现真实物理布料、背包开合、物品装载或容量模拟。
- 不制作品牌、商品购买、年度排行或产品对比功能。
- 不把结构拆解包装成真实维修或拆装教程。
- 不自建后端、模型 CMS 或在线模型编辑器。
