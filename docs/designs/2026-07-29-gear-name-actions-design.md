# 装备名称操作入口设计

## 目标

移除个人装备条目右侧的三个点按钮，让装备名称本身成为操作入口，减少视觉噪音并释放横向空间。

## 交互

- 装备名称使用可点击按钮呈现，保持单行截断和完整名称提示。
- 点击名称，在该条目下方打开紧凑操作层；再次点击同一名称时收起。
- 操作层保留“编辑名称”“更改系统”“移到待购买”和“删除”。
- 待购买装备继续在行尾显示“已买到”，不放入名称操作层。
- 编辑、更改系统和删除确认继续使用现有行内状态；删除仍需二次确认。
- 切换“已有装备 / 待购买”时关闭所有已展开状态。

## 视觉与可访问性

- 完全移除三个点按钮和“更多操作”可访问名称。
- 名称按钮占用剩余行宽，左对齐，使用现有 forest 色板和 `gear-pressable` 即时反馈。
- 移动端名称按钮保持至少 44px 触控高度；桌面端恢复紧凑高度。
- 名称按钮通过 `aria-expanded` 表达操作层状态，并保留清晰的键盘焦点样式。
- 操作层沿用 180ms `gear-surface-enter` 动画与减少动态效果设置。

## 范围

- 仅修改 `GearInventorySystemCard` 及对应静态测试。
- 不修改 IndexedDB、装备数据模型、归类逻辑、六大系统布局或其他页面。

## 验收

- 页面源码和可见 UI 中不再存在三个点或“更多操作”按钮。
- 点击任一装备名称可打开并关闭对应操作层。
- 编辑、更改系统、状态移动、已买到和二次确认删除仍正常。
- 1440×900 下 19 件装备继续一屏可见。
- 390×844 下无横向溢出，名称按钮触控高度不少于 44px。
- 装备相关测试、全量 Node 测试、Vite production build 和 `git diff --check` 通过。
