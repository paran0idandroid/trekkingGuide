# 乌孙古道地图体验设计

## 目标

为乌孙古道详情页增加接近 Komoot 信息结构与交互体验的专业徒步地图，同时保留项目自己的视觉语言、路线内容和数据来源。

第一阶段只改造乌孙古道。珠峰东坡及未来路线继续使用现有详情页，待乌孙样板完成验证后再决定是否推广。

## 已确认范围

包含：

- MapLibre GL JS 交互地图
- 基于 OpenStreetMap 数据的矢量底图
- 乌孙古道完整轨迹
- 起点、终点、营地、垭口、河流和核心景点
- 点击节点显示照片与简短介绍
- 桌面端双抽屉布局
- 移动端三段式底部抽屉
- 地图下方继续保留现有路线介绍、亮点、行程、风险和装备内容

不包含：

- 在线路线规划
- 实时导航
- 用户上传或编辑轨迹
- 离线地图下载
- 多底图切换
- 使用 Komoot 的样式文件、瓦片、图片、图标、接口或其他专有资源
- 将该地图组件立即推广到其他路线

## 技术方案

### 地图引擎

新增 `maplibre-gl` 作为唯一地图渲染依赖。选择原因：

- 支持 WebGL 矢量瓦片和 GeoJSON
- 原生支持路线、节点、缩放、拖动和视野适配
- BSD 许可证允许在项目中使用
- 项目维护活跃，生态成熟
- Komoot 当前页面同样使用 MapLibre，能力模型与目标一致

该依赖是项目“不新增未列依赖”规则的一次明确例外，已获得用户确认。

### 地图数据

第一版使用 OpenFreeMap 提供的 OpenStreetMap 矢量瓦片与公开样式作为底图基础。地图上必须显示清晰且不可遮挡的 OpenStreetMap 贡献者署名。

不得直接调用 Komoot 的瓦片、样式或内部接口。不得把 `tile.openstreetmap.org` 作为生产环境的矢量底图服务。

底图服务通过独立配置常量注入 MapLibre，避免把供应商地址散落在组件内，便于未来替换为其他 OSM 服务或自托管瓦片。

### 轨迹数据

来源文件：`/Users/jon/Downloads/乌孙古道.kml`。

已确认文件包含：

- 9,793 个连续轨迹点
- 9,793 个时间戳
- 逐点海拔
- 起点和终点
- 约 162 个用户标注点
- 记录距离约 106.87 千米
- 累计爬升 6,458 米
- 累计下降 6,553 米

KML 不直接随网站发布。实现阶段生成精简 GeoJSON，只保留：

- 简化后的轨迹坐标及海拔
- 起点与终点
- 经人工确认的营地、垭口、河流和核心景点
- 地图渲染需要的稳定标识和分类

必须移除：

- 用户 ID、设备信息和应用版本
- 原作者昵称等个人元数据
- 两步路远程图片链接
- 与路线介绍无关的随手标注
- 不适合作为公共路线建议的主观或危险捷径标注

轨迹简化必须保持起终点、转折和关键节点位置，不能用现有 8 个示意坐标替代真实轨迹。

## 页面结构

### 乌孙古道详情页

乌孙古道详情页顶部使用 `RouteMapExperience` 替换当前纯图片 Hero。地图区域接近一个桌面视口高度。现有的 `Overview`、`Highlights`、`Timeline`、`Risks` 和装备内容继续保留在地图下方。

其他路线保持现状。页面根据 `route.slug === 'wusun'` 选择地图体验或现有 Hero，第一阶段不建立额外的地图配置抽象。

### 组件边界

- `RouteMapExperience`：组织桌面与移动端布局，持有选中节点状态。
- `RouteMapCanvas`：初始化和销毁 MapLibre，绘制轨迹与节点，向父组件报告节点选择。
- `RouteNodeList`：展示经过筛选的路线节点，通过 props 接收数据。
- `RouteDetailPanel`：展示路线摘要或当前节点详情。
- `RouteMobileSheet`：实现移动端三段式底部抽屉。

所有组件使用默认导出。Props 接口定义在组件文件顶部。组件不得直接导入 `routeDataMap` 或具体路线常量；路线内容由页面通过 `getRouteBySlug()` 获取并以 props 传入。

## 视觉设计

### 桌面端

采用已确认的 Komoot 式双抽屉结构：

- 地图占据整个顶部区域，作为主视觉背景。
- 左侧第一个白色浮动抽屉展示节点列表。
- 左侧第二个白色浮动抽屉展示路线摘要或当前节点详情。
- 右侧只保留必要的缩放、定位和适应轨迹控件。
- 轨迹使用白色描边加森林绿色主线，保证在复杂底图上的可读性。
- 卡片、按钮和标签使用项目现有 `forest-*` 与 `sand-*` 色板。

### 移动端

采用已确认的三段式底部抽屉：

1. 收起状态：显示路线名称、距离、天数和累计爬升。
2. 中间状态：显示节点列表。
3. 展开状态：显示当前节点的完整照片和介绍。

底部抽屉展开时不能让地图完全失去上下文。触摸拖动必须和地图平移手势隔离。

### 可读性

- 常规文字不使用低于 75% 的不透明度。
- 地图上的小号文字和节点标题必须保持清晰。
- 白色浮动卡片使用明确阴影或边界，与浅色地图区域区分。
- 用户可见文案使用中文。

## 数据流与状态

1. `RoutePage` 通过 `getRouteBySlug(routeSlug)` 获取路线内容。
2. 乌孙古道地图 GeoJSON 由页面或地图体验组件按固定 URL 加载。
3. `RouteMapExperience` 保存 `selectedNodeId` 和移动端抽屉状态。
4. 地图点击节点时，`RouteMapCanvas` 回调节点 ID。
5. 节点列表点击时，通过相同状态更新详情，并让地图平滑聚焦对应坐标。
6. 桌面详情面板和移动端底部抽屉从同一份节点数据读取内容。

不把 MapLibre 实例放入 React 状态。实例只保存在 `useRef` 中，并在组件卸载时销毁。

## 错误处理

遵守项目“不做隐式兜底”的原则：

- 底图加载失败时显示明确的中文错误状态，不切换回虚假地图。
- GeoJSON 加载或解析失败时显示“路线轨迹暂时无法加载”，不绘制示意线。
- 节点引用不存在时暴露开发错误，不静默选择第一个节点。
- 地图初始化失败时记录可诊断错误，并保持下方路线正文可阅读。

## 性能

- KML 在实现阶段离线转换，不在浏览器中解析 1.3 MB 原文件。
- 对 9,793 个轨迹点进行有误差上限的几何简化。
- 节点图片使用项目本地 WebP，不依赖两步路远程资源。
- 地图组件只在乌孙古道路由加载，避免增加其他页面的首屏包体。
- 后续根据构建结果决定是否对 MapLibre 做路由级动态导入；第一版不提前增加复杂抽象。
